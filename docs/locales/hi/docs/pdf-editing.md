# PDF टेक्स्ट संपादन

स्थिर टेक्स्ट-बॉक्स ID और मूल पाठ प्राप्त करने के लिए स्रोत फ़ाइल का निरीक्षण करें:

```python
from onekit.api import execute
from onekit.models import Artifact

source = Artifact("document.pdf", open("document.pdf", "rb").read())
inspection = execute("pdf-edit", [source], {"mode": "inspect"})
box = inspection.details["pages"][0]["runs"][0]
result = execute("pdf-edit", [source], {
    "edits": [{"page": 1, "id": box["id"], "original": box["text"], "text": "Updated text"}]
})
open("edited.pdf", "wb").write(result.files[0].data)
```

CLI उसी विकल्प वस्तु को स्वीकार करता है जिसके माध्यम से `--options`. `edits` हो सकता है JSON सरणी या एक स्ट्रिंग जिसमें उस सारणी शामिल है। निरीक्षण मोड आउटपुट `*.text-boxes.json`; मोड आउटपुट संपादित करें `*.edited.pdf`. मूल रखें PDF निरीक्षण और संपादन के बीच अपरिवर्तनीय। पुरानी पड़ चुकी ID, दोहराए गए संपादन और मेल न खाने वाला मूल पाठ अस्वीकार किए जाते हैं।

स्कैन को पहले OCR की आवश्यकता होती है। पुन: प्रयोज्य फॉर्म XObjects के अंदर पाठ, पाठ ऑपरेटरों को उद्धृत करें, ऊर्ध्वाधर लेखन और कतरन पाठ प्रत्यक्ष संपादन के लिए पेश नहीं किए जाते हैं। अधूरे मैपिंग वाले फ़ॉन्ट भी अनुपलब्ध हो सकते हैं। एक प्रतिस्थापन चरित्र मूल फ़ॉन्ट मैपिंग में मौजूद होना चाहिए; इंजन चुपचाप फ़ॉन्ट बदलने के बजाय असमर्थित वर्णों की रिपोर्ट करता है। संपादन एकल-लाइन है और पैराग्राफ को फिर से प्रवाहित नहीं करता है। गोपनीय जानकारी को हटाने के लिए एक समर्पित रिडैक्शन टूल का उपयोग करें, जिसमें एनोटेशन, दस्तावेज़ इतिहास, मेटाडाटा या अन्य PDF ऑब्जेक्ट्स में प्रतियां शामिल हैं।

पिछले `text`, `x`, `y`, `page` विकल्प उन लिपियों के लिए उपलब्ध हैं जो पाठ ओवरले जोड़ते हैं। मौजूदा पाठ को बदलने के लिए `edits` की आपूर्ति करें।
