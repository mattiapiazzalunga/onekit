# प्रसंस्करण सेवाएं

`ExecutionContext` उपकरण विकल्पों के स्वतंत्र रूप से विश्वसनीय स्थानीय इंजन प्राइमिटिव की आपूर्ति कर सकते हैं। प्रसंस्करण API इनपुट कलाकृतियों को मान्य करना जारी रखता है, बजट लागू करता है और आउटपुट कलाकृतियों की जांच करता है। एक इंजन सेवा रिटर्न रीडिंग या पिक्सेल; सार्वजनिक प्रसंस्करण हैंडलर उन रीडिंग की व्याख्या करता है और परिणाम बनाता है। सेवाओं को एक निष्पादन के लिए दायर किया जाता है और डिफ़ॉल्ट CLI इंजन को नहीं बदलता है।

वैकल्पिक सेवाओं को `ExecutionContext` पर प्रलेखित किया गया है: प्रतीक रीडिंग, OCR, भाषण मान्यता, अग्रभूमि मास्क और PDF rasterization। PDF पेज रिकॉर्ड्स ने अंक में रेस्टर डेटा और भौतिक आयामों को एन्कोड किया। रास्टर एन्कोडिंग, स्लाइड असेंबली और विनाशकारी रिडैक्शन सार्वजनिक हैंडलर में रहते हैं। भाषण रिकॉर्ड एक भाषा और स्टार्ट / एंड / टेक्स्ट सेगमेंट की सूची का उपयोग करते हैं। OCR रिकॉर्ड में टेक्स्ट या सर्च करने योग्य PDF बाइट्स प्रति पेज होते हैं, जिसमें रीस्कलिंग के लिए वैकल्पिक भौतिक आयाम होते हैं।

JavaScript प्रोसेसिंग मॉड्यूल स्वतंत्र रूप से Python ड्राइवर से उपयोग करने योग्य हैं:

- `tools/developer/source_engine.mjs` निर्यात स्रोत परिवर्तन और परिणाम हैंडलिंग, एक मूल स्वरूपक होस्ट इंटरफ़ेस, वाक्यविन्यास-त्रि जाँच, स्थानीय JSON सूचक सत्यापन, API विनिर्देश चयन और कंटेनर नुस्खा प्रसंस्करण। इंजन लोड हो रहा है, प्रक्रिया अलगाव और पार्सर जीवनकाल कॉलर से संबंधित हैं।
- `tools/document_engine.mjs` Pandoc दस्तावेज़ नोड्स की एक सबसेट का उपयोग करके बुनियादी semantic दस्तावेज़ रूपांतरण का निर्यात करता है। यह Markdown और HTML पार्सर सेवाओं को स्वीकार करता है, सक्रिय सामग्री और बाहरी छवियों की लोडिंग को छोड़ देता है, और स्टैंडअलोन LaTeX लिखते हैं। एक PDF लेखक सेवा को अर्थपूर्ण दस्तावेज़ प्राप्त होता है; लेआउट, फ़ॉन्ट संसाधन और प्रतिपादन उस लेखक से संबंधित हैं। पार्सर जटिलता सीमा कॉलर पैरामीटर हैं।

दस्तावेज़ सबसेट पैराग्राफ, शीर्षकों, जोर, कोड, लिंक, सूचियों, उद्धरण और क्षैतिज नियमों को कवर करता है। तालिकाओं को पाठ पंक्तियों द्वारा दर्शाया गया है। यह एक दस्तावेज़ टाइपसेटिंग इंजन की पूरी कार्यक्षमता का दावा नहीं करता है। मौजूदा मूल CLI दस्तावेज़ रूपांतरण अपने मूल इंजन अनुबंध के साथ उपलब्ध है।

मूल दस्तावेज़ निष्पादन के बिना स्थापना के लिए, Python प्रसंस्करण API भी `ExecutionContext(portable_documents=True)` स्वीकार करता है। Markdown/HTML से PDF या LaTeX तब `tools/portable_documents.py` का उपयोग करता है: बाध्य स्थानीय HTML पार्सिंग, मार्कडाउनइट, एस्केप किया हुआ LaTeX और इसके बंडल वेरा फोंट के साथ रिपोर्टलैब लेआउट। यह कभी संसाधन प्राप्त नहीं करता और न ही स्रोत मार्कअप निष्पादित करता है। यह जानबूझकर मूल मोड omits CSS और सक्रिय सामग्री, पाठ पंक्तियों के रूप में तालिकाओं का प्रतिनिधित्व करता है, बिना समर्थित PDF glyphs को अस्वीकार करता है। `DocumentLimits` इनपुट और आउटपुट बाइट सीमाओं के स्वतंत्र रूप से नोड, घोंसला, ब्लॉक और PDF पृष्ठ बजट को नियंत्रित करता है। `documents` और `pdf` अतिरिक्त स्थापित करें। मूल Pandoc/TeX रूपांतरण डिफ़ॉल्ट रहता है; उन मूल पथों के लिए विशेष रूप से परिवर्तन पोर्टेबल मोड को प्रभावित नहीं करते हैं।

`tools/symbols.py` मूल स्कैनिंग द्वारा उपयोग की जाने वाली ZXing रीडर सेटिंग्स को उजागर करता है। आपूर्ति पाठक समान प्रारूपों, घूर्णन और उलटा सेटिंग्स का उपभोग कर सकते हैं। बारकोड हैंडलर सार्वजनिक परिणाम को इकट्ठा करने से पहले प्रारूप आलियास को सामान्य करता है। `input_image` और `pixel_input` नेटिव रीडिंग और दिए गए पिक्सेल-आधारित रीडरों के बीच छवि की दिशा और सफेद पृष्ठभूमि पर अल्फा संयोजन साझा करते हैं। कॉलर पहचान सेटिंग्स से स्वतंत्र रूप से पिक्सेल बजट को संकीर्ण कर सकते हैं।

`tools/background.py` U2Net मॉडल checksum, `foreground_input` और `foreground_output` को उजागर करता है। इनपुट आकार `[1,3,320,320]` के साथ एक सन्निहित little-endian float32 टेंसर है; आपूर्ति की भविष्यवाणी आकार `[1,1,320,320]` के साथ पहला फ्लोट32 आउटपुट है। दोनों मूल अनुमानों और आपूर्ति की भविष्यवाणी समान टेंसर तैयारी, मुखौटा सामान्यीकरण और छवि का आकार बदलने का उपयोग करते हैं। Inference रनटाइम मतभेद अभी भी फ्लोटिंग पॉइंट परिणामों को प्रभावित कर सकते हैं।

`tools/transcription.py` मॉडल, भाषा, नमूना दर, बीम चौड़ाई और पिछले पाठ कंडीशनिंग सहित `recognition_parameters` को उजागर करता है। एक अलग अनुमान होस्ट को स्पष्ट रूप से उन सेटिंग्स का समर्थन करना चाहिए; साझा सेटिंग डिकोडिंग कार्यान्वयन या quantized मॉडल रूपांतरणों की समतुल्यता स्थापित नहीं करती है।

डेवलपर हैंडलर अपने Python वातावरण में स्थापित होने पर सीधे SQLparse और SQLFluff का उपयोग करता है। मूल स्टैंडअलोन `sqlformat` और `sqlfluff` आदेश जब उन आयात अनुपलब्ध हैं समर्थित रहते हैं। SQL सत्यापन अनुरोधित SQLFluff बोली का उपयोग करता है, जिसमें ANSI डिफ़ॉल्ट के रूप में होता है; यह प्रश्नों को निष्पादित नहीं करता है।

साझा संसाधन छत को `src/onekit/limits.py` में परिभाषित किया गया है। कॉलर उन्हें `ExecutionContext` के माध्यम से कस सकते हैं; वे कोर छत को नहीं बढ़ा सकते।
