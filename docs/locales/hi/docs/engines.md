# बाह्य इंजन और लाइसेंस

मालिक ने ओपन सोर्स इंजन को अलग से स्थापित करने की मंजूरी दे दी। वे Python wheel, स्रोत डाउनलोड या प्रारंभिक डोकर छवि में बंडल नहीं हैं। `onekit doctor` आवश्यकताओं की रिपोर्ट करता है। `ONEKIT_ALLOW_COPYLEFT=0` स्पष्ट रूप से सूचीबद्ध copyleft एडाप्टर को निष्क्रिय करता है। अद्यतन अपस्ट्रीम उपकरण रखें; स्थानीय उप-प्रक्रियाएं शत्रुतापूर्ण दस्तावेजों के लिए एक पूर्ण सैंडबॉक्स नहीं हैं।

| इंजन | कमान | उपयोग / लाइसेंस विचार |
| --- | --- | --- |
| LibreOffice | `soffice` / `libreoffice` | कार्यालय → PDF/images; MPL और तीसरे पक्ष के नोटिस। |
| Pandoc | `pandoc` | उन्नत मार्कअप रूपांतरण; GPL। |
| TeX Live/pdfTeX | `pdflatex` | LaTeX/Pandoc PDF; इंजन, मैक्रोज़ और फोंट्स में अलग लाइसेंस हैं। |
| FFmpeg | `ffmpeg` | मीडिया; निर्माण और कोडेक के आधार पर LGPL या GPL। |
| veraPDF | `verapdf` | अभिलेखीय आउटपुट का वैकल्पिक स्वतंत्र सत्यापन; अपस्ट्रीम GPL/MPL और Java आवश्यकताओं। |
| ExifTool | `exiftool` | समर्थित फ़ाइल प्रकारों में मेटाडाटा; अपस्ट्रीम पर्ल लाइसेंसिंग। |
| Tesseract | `tesseract` | OCR; अपाचे इंजन और अलग से लाइसेंस प्राप्त भाषा डेटा। |

यदि इन कार्यक्रमों को वितरित किया जाता है, जिसमें डॉकर शामिल हैं, तो उनके लाइसेंस/नोटिस को संरक्षित करें और आवश्यक संबंधित-स्रोत/निर्माण सामग्री प्रदान करें। आकलन AGPL अलग से नेटवर्क एकीकरण। व्यावसायिक उपयोग और स्रोत / पुनर्वितरण दायित्व अलग-अलग प्रश्न हैं। अलग प्रक्रियाएं सार्वभौमिक रूप से दायित्वों को समाप्त नहीं करती हैं। आधिकारिक पढ़ें [FFmpeg](https://ffmpeg.org/legal.html), [लिबर ऑफिस](https://www.libreoffice.org/licenses/), [Ghostscript](https://www.ghostscript.com/licensing/) और [MPL](https://www.mozilla.org/en-US/MPL/2.0/FAQ/) एक बंडल वितरण बनाने से पहले सामग्री।

कार्यालय निष्ठा फ़ॉन्ट्स और संसाधनों पर निर्भर करती है। PDF-to-Word निकाले गए पाठ निर्यात; PDF-to-PowerPoint छवि स्लाइड बनाता है। PDF मरम्मत सबसे अच्छा प्रयास है; संपीड़न हानिरहित है। [PDF/A रूपांतरण और सत्यापन](pdfa.md) अलग-अलग MPL साझा के माध्यम से पुस्तकालय Python एडाप्टर, बंडल लाइसेंस के साथ ICC प्रोफाइल। Ghostscript की आवश्यकता नहीं है। स्वतंत्र मानक सत्यापन की सिफारिश की गई है। OCR सटीकता स्कैन गुणवत्ता और भाषा पैक पर निर्भर करती है।

## प्रोग्रामिंग टूल

निश्चित संस्करणों वाले WASM पैकेजों से Kotlin को ktfmt और Ruby को Syntax Tree तथा RuboCop के साथ फ़ॉर्मैट करता है। `onekit engines install` चलाएँ। प्रत्येक इनपुट फ़ाइल अधिकतम 256 KiB की हो सकती है; परियोजना का कॉन्फ़िगरेशन लोड नहीं किया जाता।

tex-fmt और निश्चित सेटिंग से LaTeX का प्रारूपण करता है। प्रोजेक्ट कॉन्फ़िगरेशन लोड नहीं होता। प्रत्येक इनपुट फ़ाइल अधिकतम 256 KiB की हो सकती है।

Pandoc 3.9 से स्वयंपूर्ण LaTeX दस्तावेज़ बदलता है। बाहरी फ़ाइलें और TeX संकलन समर्थित नहीं हैं। प्रत्येक इनपुट फ़ाइल अधिकतम 256 KiB की हो सकती है।

`dev-format-latex`: `Node.js 24+`; `tex-fmt` WASM, MIT. `latex-to-html`, `latex-to-md`: `onekit setup latex-to-html`; `pandoc-wasm@1.1.0`, GPL-2.0-or-later; `ONEKIT_PANDOC_ENGINE_PATH`, `ONEKIT_ALLOW_COPYLEFT=0`.

Node.js 24+ स्थापित करें और बंद किए गए Prettier/plugins, esbuild, HTML minifier, SVGO और GraphQL.js के लिए `onekit engines install` चलाएं। वे उपयोगकर्ता के OneKit कैश में स्थापित होते हैं, जो वैश्विक रूप से नहीं। `ONEKIT_NODE_ENGINE_PATH` विकल्प चुनता है। एक अनुमोदित इंजन अद्यतन के बाद इंस्टॉलर को फिर से शुरू करें। पार्सर समूह में JS/TS/JSX/TSX, मार्कअप, स्टाइलशीट, Markdown/MDX, GraphQL, Vue, Svelte, एस्ट्रो, Solidity और PHP शामिल हैं।

अपने ओएस के लिए अपस्ट्रीम compilers / लांचरों को स्थापित करें और पीएटीएच को दस्तावेज कमांड जोड़ें। कुछ पृथक फ़ाइलों को उनकी परियोजना निर्भरता या सटीक Java वर्ग फ़ाइल नाम की आवश्यकता होती है। प्रारूपण/parser सत्यापन परियोजना-व्यापी प्रकार की शुद्धता को साबित नहीं करता है।

पर Windows, Bash/Shell एडाप्टर PATH पर एक वास्तविक अनुवादक को पसंद करते हैं और फिर Git का पता लगाते हैं Windows अपने मानक प्रणाली / उपयोगकर्ता स्थापना निर्देशिकाओं में। System32 WSL लॉन्चर को एक संगत स्थानीय पार्सर के रूप में नहीं माना जाता है। PowerShell सिंटैक्स सत्यापन की आवश्यकता है `pwsh`इसके अलावा प्रारूपण के लिए PSScriptAnalyzer (Pscriptanalyzer) की आवश्यकता होती है।`Install-Module PSScriptAnalyzer -Scope CurrentUser`). `onekit doctor dev-format-powershell` उस मॉड्यूल को अलग से जांचें और इसके सेटअप कमांड की रिपोर्ट करें। ये प्रोग्राम/ मॉड्यूल फाइलों को संसाधित करते समय डाउनलोड नहीं किए जाते हैं।

## प्लेटफ़ॉर्म संबंधी शर्तें

CI लाइसेंस चेक भी अलग हस्ताक्षर करने के अतिरिक्त स्थापित और अनुप्रस्थ करता है ()`scripts/check_licenses.py --include-signing`). MIT-0 एक permisive लाइसेंस के रूप में मान्यता प्राप्त है ()[SPDX पाठ](https://spdx.org/licenses/MIT-0.html)). बंद `certifi` 2026.7.22 मोज़िला ट्रस्ट स्टोर डेटा एक स्पष्ट संस्करण-विशिष्ट है MPL-2.0 अपवाद; इसे पुनर्वितरण करते समय अपने असंशोधित अपस्ट्रीम लाइसेंस/नोटिस को बनाए रखें ()[अपस्ट्रीम नोटिस](https://github.com/certifi/python-certifi/blob/master/LICENSE)). नए संस्करणों को एक और समीक्षा की आवश्यकता होती है। यह अपवाद आम तौर पर अन्य स्वीकार नहीं करता है MPL पैकेज या परिवर्तन OneKit' PolyForm-Shield-1.0.0 लाइसेंस

सार्वभौमिक Python कोर समर्थन Linux, Windows और macOS सहित ARM64. नेटिव एक्स्ट्रास और बाहरी इंजन अतिरिक्त आवश्यकताओं को निर्धारित करते हैं। CI ने सभी तीन OS परिवारों पर x64/ARM धावकों को घोषित किया। पर Windows ARM, Brotli/WOFF2 और अलग हस्ताक्षर करने वाले क्रिप्टोग्राफ़ी स्टैक को मूल निर्माण उपकरण या x64 की आवश्यकता हो सकती है Python अनुकरण के तहत। WOFF/TTF/OTF आवश्यकता नहीं है WOFF2 एनकोडर। `all` अतिरिक्त अलग हस्ताक्षर को बाहर कर देता है। इन वैकल्पिक सीमाओं की सूचना दें; जब नेटिव wheel उपलब्ध न हो, तो उसकी उपलब्धता का दावा न करें।
