# Операции выпуска

Защищайте `main` и стабильные теги `v*`. Зарегистрируйте доверенного издателя PyPI для репозитория `onekit`, рабочего процесса `release.yml` и окружения `pypi`. Обновите версию пакета, lockfile, каталог и документацию, затем опубликуйте соответствующий стабильный тег SemVer из проверенного коммита.

Рабочий процесс релиза проверяет тег, выполняет необходимые проверки CLI и публикует универсальные дистрибутивы wheel/source, образ GHCR и активы релиза GitHub. `onekit-release.json` содержит версию, коммит исходного кода, контрольные суммы активов и URL для скачивания. Повторные попытки публикации должны сохранять неизменяемые активы; изменения в коде требуют новой версии.

<a id="pypi-license-metadata"></a>
## PyPI license metadata

Пакет PyPI является открытым исходным кодом (PolyForm Shield 1.0.0), с ограничением на конкуренцию, объясненным в README, отображаемом на странице проекта. `project.license` использует `LicenseRef-PolyForm-Shield-1.0.0`; wheel и архив исходников включают полный LICENSE и NOTICE. Метаданные проекта содержат ссылки на лицензию и документацию. Не добавляйте классификатор лицензии, одобренный OSI: эта лицензия ограничивает конкурирующие продукты.

Перед публикацией соберите из предполагаемого релизного коммита и проверьте реальные артефакты:

```sh
uv build
python scripts/check_distribution_licenses.py
```

CI и релизная сборка выполняют эту проверку перед публикацией артефактов. PyPI отображает README из пакета, поэтому после изменения документации или метаданных лицензии требуется пересборка. Публикуйте новую, неиспользованную версию, когда заменяете уже опубликованный релиз; существующие PyPI дистрибутивы нельзя перезаписать. Ранее распространённые версии сохраняют свои исходные условия лицензии. Версия текущей сборки не изменяется автоматически при изменении лицензии.

Владелец проекта настраивает аккаунт PyPI, Доверенного издателя и публикацию отдельно; локальная подготовка не загружает пакеты и не меняет живую страницу PyPI.

<a id="weekly-dependency-maintenance"></a>
## Weekly dependency maintenance

Dependabot следит за lockfile UV, зависимостями движка CLI Node, Docker и GitHub Actions. Плановый рабочий процесс Checks повторно тестирует заблокированные зависимости и нативные движки. Допустимые Python обновления только для lock остаются подчинены успешным проверкам и защите ветки.
