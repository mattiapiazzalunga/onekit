# Сервисы обработки

`ExecutionContext` может предоставлять надежные локальные базовые функции движка независимо от опций инструментов. Процессинг API продолжает проверять входные артефакты, применять бюджеты и проверять выходные артефакты. Сервис движка возвращает показания или пиксели; публичный обработчик процесса интерпретирует эти показания и строит результат. Сервисы ограничены одной сессией исполнения и не изменяют стандартные движки CLI.

Необязательные сервисы описаны в `ExecutionContext`: чтение символов, OCR, распознавание речи, маски переднего плана и растеризация PDF. Записи страниц PDF содержат закодированные растровые данные и физические размеры в пунктах. Кодирование растровых данных, сборка слайдов и необратимое скрытие остаются в публичных обработчиках. Записи речи используют язык и список сегментов start/end/text. Записи OCR содержат для каждой страницы текст или байты PDF с возможностью текстового поиска, а также необязательные физические размеры для масштабирования.

Модули обработки JavaScript можно использовать независимо от драйвера Python:

- `tools/developer/source_engine.mjs` экспортирует преобразование исходного кода и обработку результатов, интерфейс хоста нативного форматтера, проверки синтаксического дерева, локальную проверку указателей JSON, выбор спецификации API и обработку контейнерного рецепта. Загрузка движка, изоляция процесса и время жизни парсера относятся к вызывающему.
- `tools/document_engine.mjs` экспортирует базовое семантическое преобразование документов, используя подмножество узлов документа Pandoc. Он принимает сервисы парсера Markdown и HTML, пропускает активное содержимое и загрузку внешних изображений, и записывает автономный LaTeX. Сервис записи PDF получает семантический документ; макет, ресурсы шрифта и рендеринг относятся к этому писателю. Ограничения сложности парсера задаются параметрами вызывающего.

Подмножество документа охватывает абзацы, заголовки, выделение, код, ссылки, списки, цитаты и горизонтальные линии. Таблицы представлены текстовыми строками. Оно не претендует на полную функциональность системы верстки документов. Существующая нативная конвертация документов CLI по-прежнему доступна с оригинальными контрактами движка.

Для установок без нативных программ для обработки документов API обработки на Python также поддерживает `ExecutionContext(portable_documents=True)`. Markdown/HTML до PDF или LaTeX затем использует `tools/portable_documents.py`: ограниченный локальный разбор HTML, MarkdownIt, экранированный LaTeX и разметку ReportLab с включёнными шрифтами Vera. Он никогда не загружает ресурсы и не выполняет исходную разметку. Этот преднамеренно простой режим опускает CSS и активный контент, представляет таблицы как текстовые строки, отклоняет неподдерживаемые PDF символы. `DocumentLimits` управляет узлами, вложенностью, блоками и лимитами страниц PDF независимо от ограничений на байты ввода и вывода. Установите дополнения `documents` и `pdf`. Нативное преобразование Pandoc/TeX остаётся по умолчанию; изменения, применяемые только к этим нативным путям, не влияют на портативный режим.

`tools/symbols.py` открывает настройки считывателя ZXing, используемые при нативном сканировании. Поставляемые считыватели могут использовать те же форматы, настройки поворота и инверсии цветов. Обработчик штрихкодов нормализует алиасы форматов до того, как собрать публичный результат. `input_image` и `pixel_input` разделяют ориентацию изображения и композицию альфа-канала на белом фоне между нативным чтением и поставляемыми пиксельными считывателями. Вызывающие стороны могут ограничивать пиксельный бюджет независимо от настроек обнаружения.

`tools/background.py` раскрывает контрольную сумму модели U2Net, `foreground_input` и `foreground_output`. Входным данным является непрерывный тензор float32 в формате little-endian с формой `[1,3,320,320]`; предоставленный прогноз — это первый выходной float32 с формой `[1,1,320,320]`. Как нативное инферирование, так и предоставленные прогнозы используют одинаковую подготовку тензоров, нормализацию масок и изменение размера изображений. Различия между средами выполнения инференса все еще могут повлиять на результаты с плавающей запятой.

`tools/transcription.py` открывает `recognition_parameters`, включая модель, язык, частоту дискретизации, ширину луча и условие по предыдущему тексту. Другой хост для выполнения инференса должен явно поддерживать эти настройки; общие настройки не устанавливают эквивалентность реализации декодирования или конверсий квантизованных моделей.

Обработчик разработчика использует sqlparse и SQLFluff напрямую, когда они установлены в его окружении Python. Оригинальные автономные команды `sqlformat` и `sqlfluff` остаются поддерживаемыми, если эти импорты недоступны. Проверка SQL использует запрошенный диалект SQLFluff, по умолчанию ANSI; запросы при этом не выполняются.
