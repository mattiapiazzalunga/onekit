# Проверка ввода

Каждая запись в каталоге указывает допустимые форматы, количество файлов и пределы байтов. `onekit list --json` показывает эти значения. Как прямое выполнение, так и пайплайны соблюдают эти ограничения.

<a id="limits"></a>
## Limits

Общие ограничения на пакет: 128 MiB и 256 файлов. Текстовые файлы ограничены 8 MiB каждый, растровые изображения — 64 MiB, шрифты — 16 MiB. Для сравнения нужны ровно два входных файла. Для декодированных растровых изображений установлен общий предел 40 миллионов пикселей по всем кадрам. Распакованное содержимое архивов и файлов Office ограничено 128 MiB и 4096 элементами.

Инструменты с одним входным файлом отвергают лишние файлы. Карта конвейера намеренно применяет шаг с одним входом к каждому предыдущему результату. Коллекции выходных данных проверяются постепенно, чтобы карта шага не могла накапливать неограниченные возвращаемые данные. Для файлов CLI проверяются количество, расширения и размеры перед чтением содержимого файла, а фактические считываемые байты ограничены, даже если файл растет во время чтения.

<a id="content-rules"></a>
## Content rules

- Инструменты PDF требуют заголовки PDF и последовательное конечное место для перекрёстных ссылок. `pdf-repair` намеренно допускает повреждённые перекрёстные ссылки после проверки заголовка PDF; его парсер всё равно должен восстановить реальный PDF. Изображения, переименованные в `.pdf`, отклоняются.
- Растровые данные проверяются Pillow на соответствие формата, структуре и декодированным размерам. PNG, переименованный в JPEG, отклоняется. Экспорт через Base64 также декодирует изображение перед его принятием.
- Word, Excel и PowerPoint требуют отдельных частей контейнера ZIP и корней с пространствами имён XML. Переименование Excel в `.docx` не превращает его в Word. Количество директорий и лимиты расширения проверяются перед выделением таблицы записей ZIP или чтением частей документа.
- Шрифты требуют совпадения заголовков SFNT/WOFF, валидных ограниченных диапазонов таблиц и согласованных размеров сжатых шрифтов. Заявленное размер WOFF после распаковки не может превышать лимит байтов шрифта.
- Медиа-входы имеют явные аудио/видео расширения и сигнатуры контейнеров. FFprobe проверяет типы потоков перед FFmpeg конверсией; видеопреобразование требует видео, а аудиоконверсия требует аудио без обычных видеопотоков. Допустимо прикрепление обложки. Оба исполняемых файла регистрируются с помощью `doctor`.
- Архивы отклоняют небезопасные/дублирующиеся пути, символические ссылки, зашифрованные записи ZIP, недопустимые директории, многотомные/ZIP64 директории и неподдерживаемые конкатенированные сжатые потоки. Коэффициенты расширения ZIP ограничены. Распаковка TAR ограничена перед разбором членов/PAX, с дополнительным фиксированным допуском 4 MiB для заголовков/дополнений TAR; память декодера XZ также ограничена.
- Расшифровка принимает только зашифрованный формат OneKit и проверяет его содержимое перед восстановлением ограниченного архива. Параметры пользователя не могут увеличить установленный лимит разархивирования.
- Текстовые инструменты требуют декодируемый текст без двоичных управляющих байтов. Инструменты для разработчиков принимают их языковые расширения и нейтральный ввод `.txt`; адаптеры shell/Dockerfile также позволяют исходники без расширений. Инструменты валидации намеренно принимают синтаксически неверный исходник и возвращают `valid: false`. Конвертация кодировок использует выбранную исходную кодировку; другие текстовые инструменты требуют UTF-8..
- Инспекция, адаптеры метаданных и шифрование намеренно принимают файлы любых типов. Однако их ограничения по количеству и размеру байтов по-прежнему действуют. Проверка поврежденного или неизвестного файла поддерживается, и это не является основанием для отклонения файла только из-за его содержимого.
