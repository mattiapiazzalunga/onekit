# Внешние движки и лицензии

Владелец одобрил отдельно устанавливаемые движки с открытым исходным кодом. Они не входят в состав пакета Python wheel, загружаемого пакета исходного кода или начального образа Docker. `onekit doctor` сообщает о требованиях. `ONEKIT_ALLOW_COPYLEFT=0` явно отключает перечисленные адаптеры с копилефт-лицензиями. Своевременно обновляйте внешние инструменты; локальные подпроцессы не обеспечивают полной изоляции при обработке вредоносных документов.

| Движок | Команда | Используйте / лицензионные соображения |
| --- | --- | --- |
| LibreOffice | `soffice` / `libreoffice` | Office → PDF/изображения; MPL и уведомления третьих лиц. |
| Pandoc | `pandoc` | Продвинутое преобразование разметки; GPL. |
| TeX Live/pdfTeX | `pdflatex` | LaTeX/Pandoc PDF; движок, макросы и шрифты имеют отдельные лицензии. |
| FFmpeg | `ffmpeg` | Медиа; LGPL или GPL в зависимости от сборки и кодеков. |
| veraPDF | `verapdf` | Опциональная независимая проверка архивных данных; требования upstream GPL/MPL и Java. |
| ExifTool | `exiftool` | Метаданные в поддерживаемых типах файлов; лицензирование Perl upstream. |
| Tesseract | `tesseract` | OCR; движок Apache и отдельно лицензированные языковые данные. |

Если распространять эти программы, включая внутри Docker, сохраняйте их лицензии/уведомления и предоставляйте необходимые соответствующие исходные/сборочные материалы. Оцените сетевые интеграции AGPL отдельно. Коммерческое использование и обязательства по исходникам/распространению — это разные вопросы. Разделение процессов не устраняет обязательства автоматически. Прочитайте авторитетные материалы [FFmpeg](https://ffmpeg.org/legal.html), [LibreOffice](https://www.libreoffice.org/licenses/), [Ghostscript](https://www.ghostscript.com/licensing/) и [MPL](https://www.mozilla.org/en-US/MPL/2.0/FAQ/) перед созданием объединённого распределения.

Точность преобразования документов Office зависит от шрифтов и ресурсов. PDF в Word экспортирует извлечённый текст; PDF в PowerPoint создаёт слайды с изображениями. Восстановление PDF не гарантируется; сжатие выполняется без потерь. [Преобразование в PDF/A и проверка](pdfa.md) используют отдельные библиотеки MPL через общий адаптер Python с включёнными лицензированными профилями ICC. Ghostscript не требуется. По-прежнему рекомендуется независимая проверка соответствия стандартам. Точность OCR зависит от качества сканов и языковых пакетов.

<a id="developer-tools"></a>
## Developer tools

Установите Node.js 24+ и запустите `onekit engines install` для Prettier/плагинов с зафиксированными версиями, esbuild, HTML минификатора, SVGO и GraphQL.js. Они устанавливаются в кэш пользователя OneKit, а не глобально. `ONEKIT_NODE_ENGINE_PATH` выбирает альтернативу. Перезапустите установщик после обновления одобренного движка. Группа парсеров охватывает JS/TS/JSX/TSX, разметку, стили, Markdown/MDX, GraphQL, Vue, Svelte, Astro, Solidity и PHP.

Установите компиляторы/запускатели upstream для вашей ОС и добавьте задокументированные команды в PATH. Некоторым изолированным файлам нужны зависимости проекта или точное имя файла класса Java. Форматирование/валидация парсера не подтверждает корректность типов по всему проекту.

На Windows, адаптеры Bash/Shell предпочитают реальный интерпретатор в PATH, а затем обнаруживают Git для Windows в стандартных системных/пользовательских директориях установки. Запускатор WSL в System32 не рассматривается как совместимый локальный парсер. Проверка синтаксиса PowerShell требует `pwsh`; для форматирования дополнительно требуется PSScriptAnalyzer (`Install-Module PSScriptAnalyzer -Scope CurrentUser`). `onekit doctor dev-format-powershell` проверяет этот модуль отдельно и сообщает команду его настройки. Эти программы/модули не скачиваются во время обработки файлов.

<a id="platform-qualifications"></a>
## Platform qualifications

Проверки лицензий в CI также устанавливают и анализируют отдельный набор зависимостей для подписания (`scripts/check_licenses.py --include-signing`). MIT-0 признаётся разрешительной лицензией ([текст SPDX](https://spdx.org/licenses/MIT-0.html)). Данные хранилища доверенных центров Mozilla из закреплённой версии `certifi` 2026.7.22 составляют явное исключение для MPL-2.0, действующее только для этой версии; при их распространении сохраняйте исходную лицензию и уведомления без изменений ([исходное уведомление](https://github.com/certifi/python-certifi/blob/master/LICENSE)). Новые версии требуют повторной проверки. Это исключение не разрешает в целом другие пакеты MPL и не меняет лицензию PolyForm-Shield-1.0.0 проекта OneKit.

Универсальное ядро Python поддерживает Linux, Windows и macOS, включая ARM64. Нативные дополнения и внешние движки определяют дополнительные требования. CI заявляет x64/ARM раннеры во всех трёх семействах ОС. На Windows ARM Brotli/WOFF2 и отдельный стек криптографии для подписей могут требовать нативные инструменты сборки или x64 Python под эмуляцией. WOFF/TTF/OTF не требуют энкодера WOFF2. Дополнение `all` исключает отдельную подпись. Сообщайте об этих опциональных ограничениях, а не утверждайте, что существует нативный wheel, если его нет.
