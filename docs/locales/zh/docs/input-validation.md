<a id="input-validation"></a>
# 输入验证

每个目录条目都会声明可接受的格式、文件数量和字节限制。`onekit list --json` 会显示这些值。直接执行和管道都遵守这些规定。

<a id="limits"></a>
## Limits

每批次总上限为 128 MiB 和 256 个文件。文本输入每个文件最多 8 MiB，光栅图像最多 64 MiB，字体最多 16 MiB。差异对比必须有且仅有两个输入。解码后的光栅图像在所有帧中的像素总数最多为 4000 万。归档和 Office 文件解压后的内容最多为 128 MiB 和 4096 个条目。

单输入工具会拒绝额外文件。竖线映射故意将单输入步骤应用到每个前置输出。输出集合会逐步检查，因此映射步骤无法积累无限返回的数据。在读取文件内容前会检查 CLI 的文件数量、扩展名和大小，即使文件在读取过程中增长，实际读取的字节数也是有界的。

<a id="content-rules"></a>
## Content rules

- PDF 工具需要 PDF 文件头和一致的最终交叉引用位置。`pdf-repair` 在检查 PDF 文件头后故意允许损坏的交叉引用；其解析器仍必须恢复实际的 PDF。重命名为 `.pdf` 的图像会被拒绝。
- 栅格输入会通过 Pillow 检查实际格式、结构和解码后的尺寸。被重命名为 JPEG 的 PNG 会被拒绝。Base64 导出也会在接受前先解码图像。
- Word、Excel 和 PowerPoint 需要不同的 ZIP 容器部分和命名空间 XML 根。将 Excel 重命名为 `.docx` 并不会把它变成 Word。在分配 ZIP 条目表或读取文档部分之前，会检查目录数量和扩展预算。
- 字体需要匹配 SFNT/WOFF 头、有效的有界表格范围以及一致的压缩字体大小。声明的 WOFF 解压后大小不能超过字体的字节预算。
- 媒体输入具有明确的音频/视频扩展名和容器签名。FFprobe 在 FFmpeg 转换之前验证流类型；视频转换需要视频，音频转换需要没有普通视频流的音频。允许附加封面艺术。两个可执行文件都由 `doctor` 报告。
- 压缩档案会拒绝不安全/重复的路径、符号链接、加密的 ZIP 条目、无效的目录、多卷/ZIP64 目录以及不支持的合并压缩流。ZIP 的扩展比例是有上限的。TAR 解压在成员/PAX 解析前是有限制的，同时还有额外固定的 4 MiB 配额用于 TAR 头/填充；XZ 解码器的内存也有限。
- 解密仅接受 OneKit 加密格式，并在受限归档还原前验证其内容。用户选项无法增加强制扩展预算。
- 文本工具需要可解码的文本，不能有二进制控制字节。开发工具接受它们的语言扩展和中性 `.txt` 输入；shell/Dockerfile 适配器也允许无扩展名的源文件。验证工具故意接受语法上无效的源文件并返回 `valid: false`。编码转换使用所选的源编码；其他文本工具需要 UTF-8.。
- 检查、元数据适配器和加密故意接受任意文件类型。它们的数量/字节限制仍然适用。检查损坏或未知文件是一种受支持的操作，而不是仅因为内容而拒绝它的理由。
