# Servicios de procesamiento

`ExecutionContext` puede suministrar primitivas de motor locales confiables de manera independiente a las opciones de la herramienta. El procesamiento API sigue validando los artefactos de entrada, aplicando presupuestos y verificando los artefactos de salida. Un servicio del motor devuelve lecturas o píxeles; el manejador público de procesamiento interpreta esas lecturas y construye el resultado. Los servicios están limitados a una ejecución y no cambian los motores CLI por defecto.

Los servicios opcionales se documentan en `ExecutionContext`: lectura de símbolos, OCR, reconocimiento de voz, máscaras de primer plano y rasterización de PDF. Los registros de páginas PDF contienen datos rasterizados codificados y dimensiones físicas en puntos. La codificación raster, el ensamblado de diapositivas y la censura irreversible permanecen en los manejadores públicos. Los registros de voz usan un idioma y una lista de segmentos start/end/text. Los registros OCR contienen texto o bytes de un PDF con texto que permite búsquedas por cada página, con dimensiones físicas opcionales para cambiar la escala.

Los módulos de procesamiento JavaScript se pueden usar de forma independiente del controlador Python:

- `tools/developer/source_engine.mjs` exporta la transformación de código fuente y la gestión de resultados, una interfaz nativa de host de formateador, comprobaciones del árbol de sintaxis, validación local de punteros JSON, selección de especificaciones API y procesamiento de recetas de contenedor. La carga del motor, el aislamiento de procesos y la duración del analizador pertenecen al llamador.
- `tools/document_engine.mjs` exporta la conversión básica de documentos semánticos usando un subconjunto de nodos de documentos de Pandoc. Acepta servicios de análisis Markdown y HTML, omite contenido activo y la carga de imágenes externas, y escribe LaTeX independiente. Un servicio de escritura PDF recibe el documento semántico; el diseño, los recursos de fuentes y el renderizado pertenecen a ese escritor. Los límites de complejidad del analizador son parámetros del llamador.

El subconjunto de documentos cubre párrafos, encabezados, énfasis, código, enlaces, listas, citas y reglas horizontales. Las tablas se representan mediante filas de texto. No pretende ofrecer toda la funcionalidad de un motor de composición de documentos. La conversión nativa de documentos CLI existente sigue disponible con sus contratos de motor originales.

Para instalaciones sin ejecutables de documentos nativos, la API de procesamiento de Python también acepta `ExecutionContext(portable_documents=True)`. Markdown/HTML a PDF o LaTeX luego usa `tools/portable_documents.py`: análisis local limitado HTML, MarkdownIt, LaTeX escapado y diseño ReportLab con sus fuentes Vera incluidas. Nunca obtiene recursos ni ejecuta marcado de origen. Este modo deliberadamente básico omite CSS y contenido activo, representa tablas como filas de texto, rechaza glifos PDF no compatibles. `DocumentLimits` controla los límites de nodos, anidamiento, bloques y número de páginas PDF independientemente de los límites de bytes de entrada y salida. Instala los extras `documents` y `pdf`. La conversión nativa Pandoc/TeX sigue siendo la predeterminada; los cambios exclusivos de esos caminos nativos no afectan el modo portátil.

`tools/symbols.py` expone la configuración del lector ZXing utilizada por el escaneo nativo. Los lectores suministrados pueden usar los mismos formatos, la rotación y la configuración de inversión. El manejador de códigos de barras normaliza los alias de formato antes de ensamblar el resultado público. `input_image` y `pixel_input` comparten la orientación de la imagen y la composición del canal alfa sobre fondo blanco entre la lectura nativa y los lectores suministrados basados en píxeles. Los llamantes pueden reducir el presupuesto de píxeles de forma independiente a la configuración de detección.

`tools/background.py` expone la suma de verificación del modelo U2Net, `foreground_input` y `foreground_output`. La entrada es un tensor contiguo little-endian de float32 con forma `[1,3,320,320]`; la predicción proporcionada es la primera salida float32 con forma `[1,1,320,320]`. Tanto la inferencia nativa como las predicciones proporcionadas usan la misma preparación del tensor, normalización de máscara y redimensionamiento de imagen. Las diferencias entre los entornos de ejecución de inferencia aún pueden afectar los resultados de punto flotante.

`tools/transcription.py` expone `recognition_parameters`, incluyendo modelo, idioma, tasa de muestreo, ancho del haz y condicionamiento de texto previo. Un host de inferencia diferente debe soportar explícitamente esas configuraciones; las configuraciones compartidas no establecen equivalencia de implementaciones de decodificación o conversiones de modelos cuantificados.

El manejador de desarrollador usa sqlparse y SQLFluff directamente cuando están instalados en su entorno Python. Los comandos independientes originales `sqlformat` y `sqlfluff` siguen siendo compatibles cuando esas importaciones no están disponibles. La validación de SQL utiliza el dialecto de SQLFluff solicitado, con ANSI como predeterminado; no ejecuta consultas.
